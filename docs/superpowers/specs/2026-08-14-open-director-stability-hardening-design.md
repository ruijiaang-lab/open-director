# Open Director 稳定性完善设计

**日期：** 2026-08-14

**目标：** 在保留现有 React、Zustand、React Three Fiber 架构和外置模型库约定的前提下，修复上一轮完整审计中确认的高、中风险问题，并建立可持续回归门禁。

## 范围

本轮覆盖四个可独立验收的单元：

1. AI 指令与 3D 运行时安全。
2. 全景、工程文件与视频导出的数据生命周期。
3. 时间轴、播放和跨机位选择一致性。
4. Host Bridge、可见错误反馈、lint、CI 和 README。

不包含整体 UI 改版、外置模型资源内置、状态库替换或为了消除构建体积警告而进行的大规模拆包。

## 设计原则

- 危险动作必须有显式确认，名称解析必须拒绝空值和歧义。
- 用户导入的数据必须在进入主状态前校验；单个坏资源不得拖垮整个画布。
- 临时 URL、媒体流、宿主监听器和临时状态都必须有明确的创建、替换和释放路径。
- 时间轴的选择状态必须携带并校验 `cameraId`，不允许跨机位复用同名节点 ID。
- 每项修复先写失败测试，再写最小实现；最终以全量测试、构建和浏览器回归作为完成证据。

## 1. AI 与运行时安全

对象和机位只接受去除首尾空格后的完整名称匹配。缺少名称或只匹配到相似名称时返回可读错误，不再退化到 `includes("")`。向量参数要求三个有限数字；FOV、缩放和播放时间在统一边界内归一化；姿势命令只允许作用于带 `characterRig` 的角色。

AI 面板继续自动执行普通创建和调整命令，但包含 `delete_object` 或 `clear_scene` 的批次进入待确认态。面板展示模型原始摘要和危险动作列表，只有用户点击“确认执行”后才调用执行器；取消不会改动工程。

`PointerLockControls` 只监听 3D 画布选择器。导入模型以单资源错误边界隔离，加载失败时在原位置显示错误占位并通过可见状态提示用户。工具栏导入、全景和截图错误均显示在视口内；导演视角截图失败时恢复原项目和视角。

## 2. 数据与媒体 I/O

全景导入不再把 `blob:` 地址写进工程。原始 2:1 图片通过 `FileReader` 转成持久化 Data URL；需要适配的图片继续使用画布生成 Data URL。添加新全景时原子替换旧全景资源，删除时清理所有指向旧全景的对象引用。

工程 JSON 在 `JSON.parse` 后进行版本、基础字段、有限数字、枚举、ID 唯一性和引用关系校验。解析失败抛出带字段路径的错误，界面捕获并显示；成功后才整体替换工程。工程入口挂载到场景侧栏，导出使用下载文件并在点击后释放临时 URL。

视频导出先按 MP4、WebM 的兼容候选探测，再以录制器实际 `mimeType` 或最终 Blob 类型决定文件扩展名。异常路径必须停止录制器、关闭媒体轨道、恢复原视角和播放状态。

## 3. 时间轴与播放

段更新使用 `patch.duration !== undefined` 和 `patch.holdAfter !== undefined`，允许停顿归零。时间轴只有在选择记录的 `cameraId` 等于当前机位时才读取或编辑对应节点、片段和手柄；切换机位时暂停播放、播放头归零并清理旧选择。

播放帧发现当前机位不存在、节点不足两个或路径总时长无效时立即暂停，而不是保留“播放中”状态。导出和交互测试覆盖切换机位、删除路径和播放到末尾三种状态转换。

## 4. 集成与质量门禁

`App` 的宿主桥接 effect 返回清理函数。UI 文案明确说明 API Key 本地保存且请求时会发送到配置服务。项目加入 ESLint flat config、`lint` 脚本和 GitHub Actions，CI 执行 lint、测试与构建。README 不再记录会快速过期的精确测试数量，改为可复现命令和当前浏览器支持说明。

## 验收

- 所有新增测试先确认在旧实现上失败，再在新实现上通过。
- `npm run lint`、`npm test -- --reporter=dot`、`npm run build` 全部成功。
- 浏览器验证：AI 危险操作确认、AI/设置点击不触发 Pointer Lock、坏模型不崩画布、全景刷新后仍可用、无效工程给出错误、跨机位时间轴无串写、截图失败可恢复。
- 保留用户当前未提交改动；不提交、不推送。
